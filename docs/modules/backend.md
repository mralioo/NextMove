# `backend/` — operator API, chat bridge, analytics data

**Purpose.** The single HTTP surface of the system for the UI and any operator tool. FastAPI app on port **8770** (`OPERATOR_API_PORT`), serves the built UI at `/app/`. Endpoint reference: [`../api_reference.md`](../api_reference.md) · generated table: [`../generated/operator_api.md`](../generated/operator_api.md) · Swagger at `/docs`.

| File | Responsibility |
| --- | --- |
| `operator_api.py` | The FastAPI app: chat (`/chat`, `/chat/stream`), conversations, feedback loop, turns / artifacts / precedents, graph admin, replay (`/ops/*`), analytics (`/status`, `/stations`, `/flows/*`, `/closures`, `/centrality`, `/energy`, `/cascade`), static UI. Pydantic bodies: `ChatBody`, `ScoreBody`, `ActionBody`, `FeedbackBody`, `PatchBody`, `CascadeBody`. `_prepare_chat` decides the topic-switch choice and session; `_finish_chat` adds the `context` |
| `chat_bridge.py` | Talks to the ADK server: `ask()` (`/run`), `ask_stream()` (`/run_sse`, generator of `step` / `answer` / `error`), `EventParser` (incremental ADK event → operations-log steps with `stage` dispatcher \| analyst \| inspector \| writer, and the final response with tokens, timing, counts), `parse_events()`. `AgentUnavailable` → HTTP 503. ADK URL: `ADK_URL`, else `.run/services.json`, else `:8000` |
| `ops_data.py` | Replay data for the Operator Desk: topology, line colours, `snapshot(at)` (flows vs typical, active closures with blocked edges, events, weather, alerts), `series(date)`; `world()` = the merged data everything else reads |
| `analytics_data.py` | Data for the analytics tabs: `status`, `stations`, `edges`, `flows_daily`, `hourly_profile`, `heatmap`, `station_flow`, `closures`, `centrality`, `energy` (Wh per passenger, ranking + evidence, no invented interventions), `cascade` (share of typical flow diverted to open stations within *n* hops; states its method and assumption) |

## Run

`make up` starts it (service `operator-api`); alone: `./.venv/bin/python scripts/tasks.py operator-api` (foreground). Restart after code changes: `./.venv/bin/python scripts/services.py restart operator-api`.

## Behaviours worth knowing

* **One conversation = one situation.** With `context_mode: "auto"` and a message that is not clearly about the conversation's situation, the API answers `needs_choice` without calling the agent.
* **Streaming.** `/chat/stream` emits `step` frames as ADK events arrive, then `answer` (identical to `/chat`); if the agent is down: one `error` frame.
* **Nothing is generated by the API itself** except the analytics numbers, computed from the data on request (cached in memory after the first call).
* No authentication, CORS `*` by default: for `127.0.0.1` demos only.

## Tests

`tests/test_operator_feedback.py` (feedback loop, HTTP round trip, desk endpoints) and `tests/test_operator_ui_api.py` (analytics, cascade, event parser, SSE, error event) — offline, the agent is faked.

## Limits

Single process, in-memory caches, SQLite stores (one writer at a time); no live data feed (replay of the recorded window); analytics scan the merged CSVs, so the first call after a restart takes a second or two.
